# Report: Supported `visibleWhen` operators

This report lists the operators supported by the Technical Design Schema Editor for `visibleWhen` conditions.

Supported operators (by question type)

- radio, dropdown: `equals`, `notEquals`
- multiselect: `contains`, `notContains`  (values stored as arrays; builder uses OR semantics)
- checkbox: `equals`
- text: `equals`, `contains`, `startsWith`
- textarea: `contains`
- number: `equals`, `greaterThan`, `lessThan`
- default fallback: `equals`, `notEquals`

Notes

- Option-based questions store option IDs (not labels) in conditions.
- Multiselect uses array `value` with OR semantics in the builder; server validation accepts array values.
- Legacy string expressions (JS expressions referencing `answers[...]`) are parsed where possible and converted to the normalized object format.

Validation

The server validates that each condition is an object with either an `equals` (old) field or both `operator` and `value` fields; accepted operators are: `equals, notEquals, contains, notContains, startsWith, greaterThan, lessThan`.

Recommended QA checks

1. Confirm that condition values for option-based questions use option IDs by creating a small schema question and setting visibleWhen in the builder.
2. Test multiselect conditions with multiple selected values and verify UI and server accept arrays.
3. Verify legacy string expressions are parsed and converted correctly when switching to builder mode.
